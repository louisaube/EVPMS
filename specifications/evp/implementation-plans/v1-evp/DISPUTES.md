# Disputes — v1-evp

Arbitrated 2026-10-10 by QA, with the human's decision on [Q-PLAT-03] (the frozen foundation test may be adjusted).

ACCEPTED: [rule-evp-export-csv-format] the export is declared as text/csv with a string schema: the rule (inferred) fixes the bytes of the CSV, not the OpenAPI media type, and the frozen builder declares every response under one media type. The test now checks a single declared media type with a `string` schema; the real `text/csv; charset=utf-8` and `Content-Disposition` headers stay covered by acceptance-evp-notifications-journal-export.test.ts.
ACCEPTED: permissions POST /absences/validate-batch: the foundation refuses duplicated action codes at boot (access-check), so the matrix entry now reads `absences:validate-batch`. The audit row stays `absences:validate` with the `lot` object, as the specification only requires the action to be journaled.
REJECTED: permissions GET /sources/:key/anomalies: the route is present in `specifications/permissions.yaml` with the action `sources:anomalies`, identical to the declaration; nothing to change.
REJECTED: permissions regimes: no test contested. The matrix already states `allow: []` for every capability-gated route and delegates the role-by-role proof to acceptance-evp-roles-contract.test.ts; the `auth+custom` regime reported by `cuisine:routes` is the expected reading.
ACCEPTED: contract GET /google-sign-in/start and /callback: redirects are additions to the contract of record, not breaking changes, so `contract-changes.yaml` needs no entry. The `503` of `start` when Google is unconfigured is a developers' matter for the contract gate: a `4xx` with a stable code (the service is not ready, the client is told so) is acceptable and consistent with `/service-status`.
ACCEPTED: contract data-contract.md: the EVP tables and the `evp_app` role are additions in schema `base`, required by the request (row-level security by role and crèche). The foundation data contract is unchanged; the EVP data model is documented by `evp-module-implementation-plan.md`. No contracted column is renamed or dropped.
ACCEPTED: contract absence_pieces.absence_id: `text` without foreign key is what the sealed RLS test requires; noted as a deviation to be revisited when the suite is next reopened (the intention is a uuid with a foreign key).
ACCEPTED: contract POST /justificatifs/authorize-upload: `crecheCode` optional, derived from the dossier then from the single assigned crèche, otherwise 400. This matches rule-evp-piece-scope (the crèche is always checked) and the sealed helper.
REJECTED: session: no test contested. The user request states « Session serveur de 8 heures »; the `iat` check implements it on top of the foundation JWT lifetime. Nothing to change.
REJECTED: payfit_companies.siret is not unique: no test contested. Storing duplicates is what lets the sealed test « two PayFit companies with the same SIRET make the link uncertain » observe the anomaly; the request's « SIRET unique » is a linking rule (one certain match or none), not a database constraint.
ACCEPTED: hidden routes `/test/storage/put|get/*key`: tolerated as long as they are absent from the OpenAPI document (checked by [Q-PLAT-03]) and served only by the fake storage driver; they must not exist with the S3 driver.
ACCEPTED: sources connectors: real PayFit / Aqoona / Google Sheets connectors are out of this version's scope (credentials and endpoints unspecified); covered by the request `prompts/v2-evp-sources.md`. A refresh with the real driver ending FAILED with a generic message is the expected behaviour until then.
ACCEPTED: PayFit absence codes: unconfigured mappings yield a null `payfitCode`; the specification gives no default code, so null is the honest value. Noted for the settings screen.
ACCEPTED: [Q-PLAT-03] the OpenAPI document is served in test, with both security schemes and no test route (api/src/features/auth/tests/auth.test.ts): by human arbitration, the test now checks the 16 foundation paths as a subset (`expect.arrayContaining`) instead of the exact list; the ban on `/test/` paths and the two security schemes are unchanged. Nothing else in the file was touched.
ACCEPTED: input tolerance: the doubled `??` came from a test defect (`?${qs(...)}` while `qs` already prefixes `?`), corrected in acceptance-evp-absences.test.ts; the middleware collapsing `??` is now useless and may be removed. The `/closures/2026/01` mapping to 400 stands: rule-evp-closure-month-bounds treats any malformed month as a validation error.
