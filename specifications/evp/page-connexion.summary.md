# Connexion (`/connexion`) : état réalisé

Page publique qui remplace la connexion par mot de passe du socle. Code : `studio/src/app/features/auth/pages/LoginPage.tsx`, `shared/safeRedirect.ts`, `shared/components/EtatsEcran.tsx` ; API : `features/service-status/`, `features/google-sign-in/`, `evp-core/evp-login-block.interceptor.ts`. Plans : `v1-evp/connexion-page-implementation-plan.md`, complété par `v2-evp-sources/connexion-page-implementation-plan.md` (aucun libellé de l'écran ne change en v2), puis par `v3-evp-acces-contrats-siret/connexion-page-implementation-plan.md` (deux messages ajoutés ; code v3 non commité, aucun test de navigateur exécuté pour ce résumé). Module : `module-evp.summary.md`.

## Ce qui existe
- **État du service** (`rule-evp-login-service-status` user) : à l'ouverture, « Vérification de l'état du service… » puis `GET /service-status`. `ready` : pastille « Service prêt », titre « Le service est prêt » et bouton « Se connecter avec Google ». `unavailable` ou échec de la lecture : pastille « Service indisponible », titre « Le service est momentanément indisponible », le texte de l'API (repli « Impossible de joindre le service. Réessayez dans quelques instants. ») et « Réessayer » ; le bouton de connexion n'est pas affiché.
- **Google seul** (`rule-evp-login-google-only` user) : aucun champ de mot de passe, d'inscription ni d'oubli. Le clic fait `window.location.assign` vers `GET /google-sign-in/start?redirection=<chemin sûr>` ; le bouton devient « Redirection vers Google… » et se désactive.
- **Messages de l'`erreur`** (`rule-evp-login-domain-not-enough` user, `rule-evp-login-single-denial` inferred) : `domaine`, `non_autorise` (message unique pour compte absent, inactif ou sans crèche), `annule`, et « La connexion a échoué. Veuillez réessayer. » pour `echec` ou toute autre valeur. Alerte `role="alert"` au-dessus du bouton. Aucun détail technique ni de Google.
- **Informations de retour** : `?motif=session-expiree` (« Votre session a expiré. Reconnectez-vous. ») et `?motif=acces-retire` (« Votre accès a été retiré ou désactivé. Contactez la RH. ») en `role="status"`.
- **Redirection sûre** (`rule-evp-login-safe-redirect` inferred) : `safeRedirect` du socle pour la destination, transmise aussi à l'API qui la valide. Un utilisateur déjà connecté est renvoyé vers cette destination (`rule-evp-login-already-connected` inferred).
- **Vérification côté serveur (v2, API seulement)** : le jeton d'identité vient de la réponse de `GOOGLE_TOKEN_URL`, jamais du navigateur (`rule-evp-google-token-verified-server` user, `rule-evp-google-flow-redirect` inferred, option A de Q-EVP-01). `google-id-token.verifier.ts` impose RS256 (l'`alg` du jeton n'est pas obéi), choisit la clé par `kid`, contrôle `aud`, `iss`, `exp` (tolérance de 60 s), `nonce`, `email_verified`, puis `hd` comparé au domaine configuré (jeton sans `hd` ou d'un autre domaine : `domaine`) ; cache des clés selon `max-age`, relecture sur `kid` inconnu au plus une fois par minute, clés illisibles = `echec` (`rule-evp-google-signature`, `-aud`, `-iss`, `-exp`, `-hd`, `-email-verified`, `-certs-cache`, `-certs-rotation`, `-certs-fail-closed`, `-domain-configurable`, `-endpoints-configurable`). Le compte est trouvé par `sub`, ou lié à la première connexion valide par son adresse dans une transaction qui verrouille la ligne ; un compte déjà lié à un autre `sub` est refusé en `non_autorise` sans changer la liaison (`rule-evp-google-sub-identity`, `-binding`, `-unique`, `-mismatch` inferred décision D-0008). La liaison est auditée « Liaison Google enregistrée » par « Système », sans `sub` (`rule-evp-google-sign-in-audit` inferred). Le `callback` ne répond que par `302`, y compris sur une exception inattendue, rattrapée en `erreur=echec` (`rule-evp-login-single-denial` inferred). Côté écran ces refus restent classés sous les mêmes codes `domaine`, `non_autorise`, `echec`.
- **Publique, sans donnée RH** (`rule-evp-login-public-no-hr-data` user) ; le studio ne manipule aucun jeton Google (`rule-evp-login-no-secret-in-studio` inferred).
- Textes fixes : note sur le compte Google Workspace micro-stars.fr (aucun mot de passe, aucun accès à la messagerie, à l'agenda ni au Drive) et « Les écritures dans PayFit sont désactivées. » (la mise en page commune n'est pas rendue ici). Titre d'onglet « Connexion · EVP ».

- **Deux causes de refus de plus (v3)** (`LoginPage.tsx`, `errorMessage()`) : `adresse_modifiee` (`rule-evp-google-sub-email-mismatch` user) « L'adresse de votre compte Google n'est plus celle de votre accès EVP. Demandez à la personne qui gère les accès (la RH, l'administratrice ou, si vous êtes directrice, le superadmin) de mettre à jour l'adresse de votre accès, puis reconnectez-vous. » ; `compte_recree` (`rule-evp-google-sub-recreated` user, D-0008) « Votre compte Google n'est plus celui qui est lié à votre accès EVP : il a sans doute été recréé. Demandez à la personne qui gère les accès (…) de délier votre accès de l'ancien compte Google depuis l'écran Accès, puis reconnectez-vous : votre compte actuel sera alors relié. ». Les messages disent qui contacter et ne contiennent aucune adresse (`rule-evp-login-mismatch-no-address` inferred, `rule-evp-login-howto-who`). L'API ne rend ces deux valeurs que pour un compte admissible ; un compte absent, inactif, retiré ou sans crèche garde `non_autorise` (`rule-evp-login-mismatch-admissible-only` inferred), de sorte que `rule-evp-login-single-denial` ne couvre plus que ces cas. Une valeur inconnue garde « La connexion a échoué. Veuillez réessayer. » (`rule-evp-login-unknown-error`).
- **Côté API (v3)** : `GET /google-sign-in/callback` applique les sept cas de la décision (module : « Ce que la v3 ajoute ») ; la session émise porte la version de session du compte (`sv`), et `rule-evp-google-sub-email-change` (v2, la session s'ouvrait avec une autre adresse) n'existe plus. Un refus n'écrit rien.

## Limites connues
- Le parcours « adresse changée » puis « compte recréé » avec les vrais écrans Accès n'a pas été joué dans un navigateur.
- Plus aucune valeur de substitution Google, hors production non plus : sans `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` et `GOOGLE_PUBLIC_ORIGIN` (ou `GOOGLE_REDIRECT_URI`), `GET /service-status` répond « indisponible » (`google_not_configured`) et `start` répond `503` (`rule-evp-google-endpoints-configurable` user ; `module-evp.summary.md`).
- Le correctif du `callback` de la v2 (rattrapage des exceptions en `302`) est dans l'historique ; les changements de la v3 (deux causes, version de session) sont dans l'arbre de travail, non commités.
- Le parcours complet Google (callback, cookie de 8 h) n'a pas été essayé dans un navigateur pour ce résumé.
