# Détail d'une absence (`/declarations/:id`) : état réalisé

Fiche d'un dossier : où il en est, qui doit agir, pourquoi il est bloqué, la prochaine action, avec les décisions permises. Code : `studio/src/app/features/absences/pages/DetailAbsencePage.tsx`, `shared/components/{JustificatifUploader,StatutAbsence,EtatsEcran}.tsx` ; API : `GET /absences/:id`, `GET /absences/:id/audit`, `POST /absences/:id/{submit,validate,return,reject,cancel,mark-entered}`, `POST /justificatifs/:id/read-link` et l'envoi de pièces. Plan : `v1-evp/detail-absence-page-implementation-plan.md`.

## Ce qui existe
- **En-tête** : lien « Les déclarations » (toujours vers `/declarations`, sans reprendre les filtres précédents), titre « <Prénom Nom> · <Type> », sous-titre « <Crèche> · Contrat PayFit <identifiant> · Mois de paie : <mois année> », `StatutAbsence`. La page est remontée à chaque identifiant pour qu'un dossier ne montre jamais les actions d'un autre.
- **Les quatre questions** (`rule-evp-detail-four-questions`, `rule-evp-layout-four-questions` user) : carte « Où en est le dossier » avec progression en cinq étapes (« Déclarée », « Contrôlée », « Validée », « Saisie dans PayFit », « Présente dans PayFit », étape courante en `aria-current="step"`, « Étape N sur 5 : … ») ou, pour un dossier terminé, « Ce dossier est terminé : « Rejetée »/« Annulée » » ; « Qui doit agir » et « Prochaine action » en texte de l'API ; bandeau « Pourquoi ce dossier est bloqué » listant les blocages (`BandeVigilance`, masqué sans blocage). `rule-evp-arbitrage-rh` (user) : « À arbitrer par la RH. » est écrit dans l'alerte PayFit.
- **Contenu** (`rule-evp-detail-content` user) : carte « Dates » (période avec demi-journées, type, « Code PayFit attendu : <code> » ou « Non configuré », « Déclarée le … par … », commentaire administratif), carte « Pièces », carte « Chronologie » (antéchronologique, auteur), carte « Audit » pour la capacité `journal:read` (opération, auteur, détail). Mention de décision « Retourné/Refusé/Annulé par <nom> le jj/mm/aaaa : <motif> » pour les états `A_COMPLETER`, `REJETEE`, `ANNULEE`.
- **Actions issues de l'API** (`rule-evp-detail-actions-from-api` inferred, `rule-evp-detail-no-general-edit` user) : seuls les boutons présents dans `allowedActions` s'affichent : « Soumettre à nouveau », « Valider », « Saisie effectuée », « Retourner pour complément », « Refuser », « Annuler la déclaration », « Ajouter un justificatif » ; le premier est le bouton principal. Aucun formulaire d'édition. Décisions réservées à RH par l'API (`rule-evp-decision-marine-only` user).
- **Dialogues** : « Valider ce dossier ? » (rappel que valider ne transmet rien à PayFit, `rule-evp-validated-is-to-enter` user) ; motif administratif obligatoire de 1 à 500 caractères avec compteur et « Sans détail médical. » pour retourner, refuser et annuler (`rule-evp-decision-reason-required` user) ; « Saisie effectuée » (le dossier reste « à vérifier » sans preuve, `rule-evp-mark-entered-no-proof` user). Les contrôles sont rejoués par l'API ; un `409 absences.validation_blocked` affiche « La validation est impossible : » suivi des motifs (`rule-evp-decision-replay-controls` user).
- **Conflit** (`rule-evp-detail-conflict-refresh` inferred) : `409 absences.decision_not_allowed` ferme les dialogues, affiche « Le dossier a changé. Il vient d’être rechargé. » et relit le dossier. Dossier inconnu ou hors périmètre : écran « Dossier introuvable » avec « Retour aux déclarations », identique dans les deux cas (`rule-evp-detail-404-indistinct` inferred).
- **PayFit** : alerte (« Absence modifiée/annulée/non retrouvée dans PayFit », observation, ce qui a changé, « La preuve antérieure est conservée : <date>, code <code>. », `rule-evp-payfit-alerts` user) ; bandeau « Absence retrouvée à l'identique dans PayFit le … » après restauration ; carte « Observation PayFit » (date, société, code, statut source, « Confirmée automatiquement par rapprochement, jamais manuellement. ») pour `DANS_PAYFIT`. Aucun bouton ne confirme une présence PayFit (`rule-evp-payfit-no-manual-confirm` user).
- **Pièces** (`rule-evp-piece-read-link` user, `rule-evp-detail-private-piece` inferred, `rule-evp-piece-no-medical-in-logs` user) : nom, taille, « Confirmée »/« Non confirmée », « Ajoutée par <nom> », « Pièce privée » ; « Ouvrir <nom> » demande un lien de 60 s et l'ouvre dans un onglet ouvert sur le champ (lien jamais conservé ni affiché, aucun `console.log`) ; sans `canOpen`, le nom est remplacé par « Pièce privée » et « Réservée à la RH » s'affiche. L'ajout (`JustificatifUploader` avec le dossier, au plus 5 pièces au total) relit le dossier après confirmation.
- **Lecture d'une notification** : ouvrir un dossier ne change rien (`rule-evp-notification-read-no-effect` user). États de l'état d'un dossier : `rule-evp-decision-states` (user).

## Limites connues
- Un blocage de chevauchement affiche son message mais sans lien vers l'autre dossier (le plan en prévoyait un).
- Les pièces affichent « Ajoutée par <nom> » sans la date.
- La modification d'un dossier (`PATCH /absences/:id`) existe côté serveur seulement (`rule-evp-declare-edit-server` user), sans écran.
- La carte « Audit » n'apparaît que si la lecture a réussi ; un échec n'affiche rien.
- Aucun test de navigateur n'a été exécuté pour ce résumé.
