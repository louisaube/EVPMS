# Sources (`/sources`) : état réalisé

État des sources, anomalies et lecture manuelle. Code : `studio/src/app/features/sources/pages/SourcesPage.tsx` (seul fichier du studio modifié par la v2, avec `shared/notify.tsx` pour la sévérité « warning ») ; API : `features/sources/` (`GET /sources`, `POST /sources/:key/refresh`, `POST /sources/refresh-all`, `GET /sources/runs/:id`, `GET /sources/:key/anomalies`, `ReconciliationService`). Plans : `v1-evp/sources-page-implementation-plan.md`, complété par `v2-evp-sources/sources-page-implementation-plan.md` puis par `v3-evp-acces-contrats-siret/sources-page-implementation-plan.md` (seul changement de l'écran en v3 : le masquage défensif des NIR dans `SourcesPage.tsx`, code non commité, aucun test de navigateur exécuté pour ce résumé). Complétés par `v4-evp-fiabilite-nir/sources-page-implementation-plan.md` (section des taux de rattachement, voir « Ce que la v4 change »), puis par `v5-evp-rattachement-nir/sources-page-implementation-plan.md` (taux en personnes et liste des personnes non reliées, qui remplacent la section de la v4 : voir « Ce que la v5 change »). Module : `module-evp.summary.md`.

## Ce qui existe
- **Garde** (`rule-evp-sources-guard` inferred) : route sous `RequireCapability("sources:read")` (RH, superadmin) ; les autres voient « Accès refusé ».
- **Écran** (`rule-evp-sources-screen` user, `rule-evp-sources-readonly` user) : note « Les sources sont en lecture seule : EVP les contrôle puis les copie. Aucune écriture dans PayFit ni dans les autres sources. » et une carte par source renvoyée par l'API : « Google Workspace » (« Identité de connexion », « Disponible » / « Indisponible » selon la configuration Google, sans sonder Google, ni lecture ni bouton ; `rule-evp-sources-workspace-scope` user), « Google Sheets : Contacts des crèches », « PayFit », « Aqoona ». Chaque carte lue montre l'état (texte + icône), « Dernière lecture : jj/mm/aaaa à hh:mm » (date du dernier succès, conservée après un échec) ou « Jamais lue », « Fenêtre : du … au … » (PayFit M−2 à M+2, Aqoona J−28 à J+35, `rule-evp-sources-windows` user), la liste des volumes au format français, « Aucune anomalie » ou « N anomalie(s) » avec « Voir les anomalies de <source> ».
- **États** (`STATE_LABEL`) : « Jamais lue », « À jour », « Lecture en cours… », « En erreur », « Indisponible » (source non configurée), « Lecture partielle » (icône d'avertissement, puce `warning` ; `rule-evp-sources-partial-failure` inferred, décision D-0007).
- **Source non configurée** : état « Indisponible » sans erreur connue → « Source non configurée : lancez une actualisation pour connaître ce qu'il faut renseigner. » (`role="status"`) ; « Actualiser » reste disponible, la lecture se termine alors en erreur et dit ce qui manque.
- **Cause d'un échec** (`rule-evp-sources-failure-state` user, `rule-evp-secrets-never-exposed` user) : si `lastError` n'est pas nul, « Dernière tentative en échec le jj/mm/aaaa à hh:mm : <message> » (`role="status"`, couleur d'erreur). Le message est celui de l'API (1..200 caractères, secrets masqués), jamais construit par le studio ; volumes et dernière lecture restent ceux du dernier succès.
- **Adresses Aqoona** (`rule-evp-aqoona-mask` user) : une ligne « Adresse lue : <libellé> : <adresse masquée> » par élément de `addresses` (libellé de repli « Adresse N »). Par prudence, `maskAddress()` coupe tout ce qui suit le premier `?` et ajoute `?…`, quoi que l'API envoie. Texte non cliquable, aucun bouton de copie.
- **Lecture manuelle** (`rule-evp-sources-payfit-aqoona-manual` user, `rule-evp-sources-sheets-superadmin` user) : « Actualiser <source> » n'apparaît que si l'API met `canRefresh` (PayFit et Aqoona pour RH et superadmin, Contacts des crèches pour le superadmin seul) ; dialogue « Lancer la lecture de <source> ? » (« La lecture est en lecture seule et n'écrit rien dans la source. »), « Lancer la lecture », un seul envoi. « Actualiser toutes les sources » (superadmin) lit dans l'ordre Contacts des crèches, PayFit, Aqoona. Aucun ordonnanceur ni lecture automatique.
- **Suivi** (`rule-evp-sources-run-polling` inferred) : après le `202`, « Lecture en cours… » ou « Étape N sur 3 : <source> » avec barre de progression (`role="status"`), relecture de `GET /sources/runs/:id` toutes les 2 s jusqu'à la fin, arrêt en quittant la page ; une lecture déjà en cours à l'ouverture est suivie aussi. Chaque lecture lancée est journalisée par l'API (`rule-evp-sources-refresh-audited` inferred).
- **Fin de lecture** : échec → « La lecture a échoué. Consultez les anomalies et réessayez. » (erreur) ; succès → l'écran relit `GET /sources` et, si une source est `PARTIAL` avec `lastReadAt` postérieur ou égal au début de la lecture, avertit « La lecture est partielle. Consultez les anomalies. », sinon « Lecture terminée. » (`rule-evp-sources-partial-failure` inferred). Cartes relues dans tous les cas.
- **Conflit** `sources.run_in_progress` : « Une lecture est déjà en cours. » ; les cartes sont relues pour suivre la lecture lancée par quelqu'un d'autre.
- **Anomalies** : fenêtre modale paginée (10 / 25 / 50) « Type », « Élément concerné », « Détail », libellés français de l'API (aucun libellé codé dans l'écran, donc les types ajoutés par la v2 s'affichent sans code : « SIRET différent de la clé », « Type d'absence PayFit non configuré », « Demi-journée PayFit non interprétable », « Société inaccessible », « Ligne Aqoona inexploitable », « Adresse Aqoona inaccessible »). Ni NIR, ni matricule, ni donnée médicale (`rule-evp-sources-nir-discarded` user : seul un décompte et le type « Matricule écarté » existent) ; sans correspondance certaine, ligne non rattachée ou exclusion avec anomalie visible (`rule-evp-sources-no-invention` user) ; écarts RO signalés sans écraser les choix administrés (`rule-evp-sources-ro-gaps-not-overwritten` user) ; aucun signal d'absence depuis Aqoona (`rule-evp-sources-no-auto-absence` user).
- **États d'écran** : attente, erreur avec « Réessayer », « Aucune source à afficher. ».

## Ce que l'API fournit à l'écran (v2)
- `GET /sources` : `items[].lastError` (`{ code, message 1..200, at }` ou `null`, lu sur la dernière lecture terminée si elle est `FAILED`), `items[].addresses` (`[{ label 1..100, masked 1..300 }]`, vide hors Aqoona), état `PARTIAL`. Calcul d'état : `RUNNING`, puis `UNAVAILABLE` (pilote `real` et configuration incomplète), `ERROR` (dernière lecture `FAILED`), `PARTIAL` (dernière lecture réussie avec `partial`), `UP_TO_DATE` / `NEVER_READ`. Sous le pilote `fake`, le calcul de la v1 est inchangé (ni `UNAVAILABLE` ni `PARTIAL`).
- `POST /sources/refresh-all` : continue après une lecture `PARTIAL`, s'arrête à la première lecture `FAILED`. Si une source de la chaîne a été lancée seule entre-temps (`sources.run_in_progress`), l'enchaînement s'arrête avec le message « Une lecture de <source> est déjà en cours : relancez la lecture ensuite. » (`rule-evp-sources-run-single` inferred).
- Lectures réelles (pilote `real`) : Google Sheets (compte de service, `rule-evp-sheets-values-get`, plage `'<onglet>'!A:G` avec apostrophe doublée, `a1Range()`), PayFit (introspection, société par société), Aqoona (adresses à jeton, masquage unique). Détail dans `module-evp.summary.md`.

## Ce que la v3 change (lecture Aqoona « Pros »)
- **Masquage défensif des NIR** (`rule-evp-sources-nir-redaction-studio`, `rule-evp-aqoona-nir-never-stored` user) : `redactNir()` remplace par « … » toute suite d'apparence NIR (13 chiffres, ou `2A`/`2B` en 6e-7e position, clé de 2 chiffres facultative, séparateurs admis, bornée par des non-chiffres) dans le message de dernier échec, les libellés de volumes et le sujet et le détail des anomalies (tableau et cartes). Un SIRET de 14 chiffres n'est pas touché. L'API n'envoie déjà aucun NIR (`redactSecrets()` / `maskNirs()`) : c'est une seconde ligne de défense.
- **Volumes d'Aqoona** (libellés fournis par l'API, aucun codé dans l'écran) : « Plannings lus » (créneaux stockés dans la fenêtre), « Plannings rattachés » (créneaux rattachés à une collaboratrice), « Rapprochés par NIR » ; « Matricule écarté » n'est plus produit (`rule-evp-aqoona-nir-transient-key` user, qui remplace `rule-evp-sources-nir-discarded` pour ce flux).
- **Anomalies ajoutées** (libellés de l'API, affichés sans code) : « Type de créneau Aqoona inconnu » (sujet = le type normalisé, détail « N créneau(x) rangé(s) en « autre » »), « Créneau Aqoona sans type » (sujet = libellé de l'adresse), « Rapprochement par NIR indisponible » (sujet = SIRET, détail « Les noms sont utilisés à la place du NIR. »), et « Planning non rattaché » avec le détail « Rattachement par NIR ambigu » (D-0014). Aucune ne rend la lecture `PARTIAL` ni `FAILED` (`rule-evp-aqoona-slot-type-anomalies`, `rule-evp-aqoona-nir-unavailable`, `rule-evp-aqoona-nir-ambiguous` inferred).
- **Lecture** (API, détail dans le résumé du module) : adresse « Pros » seule, `dateBegin` / `dateEnd` réglés sur J−28 / J+35 (`rule-evp-aqoona-read-pros`, `rule-evp-aqoona-window-params` user), créneaux typés et dédoublonnés, correspondance de noms et d'établissements normalisée ; la lecture PayFit accepte 100 clés (`rule-evp-payfit-many-keys` user). Les adresses affichées restent masquées (`?…`, `rule-evp-aqoona-mask` user), y compris l'adresse complétée des deux dates.

- **Anomalies d'Aqoona** (libellés de l'API, aucun codé dans l'écran ; `rule-evp-nir-key-anomalies-visible` inferred, D-0018 ; `rule-evp-payfit-scope-missing-visible` user, D-0019) : « Clé de NIR Aqoona incorrecte » (élément = prénom et nom), « Clé de NIR PayFit incorrecte » (élément = prénom et nom, ou « Collaboratrice <identifiant> » ; détail = SIRET et conduite), « Rapprochement par NIR indisponible » dont le détail nomme `collaborators:social-security:read` quand la portée manque. ## Limites connues
- **v5** : tant que des créneaux d'avant la v5 restent stockés, ni taux ni liste ne s'affichent (texte « sera disponible après la prochaine lecture complète d'Aqoona »). Pas d'export, de correction, de lien vers PayFit ou Aqoona, ni de rattachement manuel : lecture seule. Le code de la v5 est dans l'arbre de travail, non commité ; aucun test de navigateur, porte ni suite n'a été exécuté pour ce résumé.
- **v4** (la section en créneaux, la colonne « par prénom et nom » et la note de la v4 sont remplacées par la v5 ci-dessus ; le reste vaut encore) : tant que des lignes d'avant la v4 (mode inconnu) restent stockées, la section n'affiche aucun taux. Après une lecture avec une adresse en échec, les créneaux conservés sont comptés dans le tableau mais pas dans les volumes de la carte. Pas d'historique, de seuil ni d'alerte. Format du champ `scope` PayFit supposé. Le code de la v4 est dans l'arbre de travail, non commité ; aucun test de navigateur, porte ni suite n'a été exécuté pour ce résumé.
- Aucune réponse « Pros » réelle ni lecture PayFit des NIR réelle n'a été faite : le nom du champ NIR de PayFit est supposé (module : « Limites connues »).
- Le pilote par défaut hors production est `fake` (fixtures) ; seul `EVP_SOURCES_DRIVER=real` (imposé en production) lit les vrais services. Les volumes et anomalies vus avec `fake` viennent de fixtures. Les lectures réelles n'ont été éprouvées que contre des serveurs factices ; aucun service PayFit, Aqoona ni Google réel n'a été appelé.
- Le fichier `api/config/aqoona-mapping.json` suit désormais le format « Pros » (`rule-evp-aqoona-mapping-final` user, qui remplace `rule-evp-aqoona-mapping-provisional`), mais il n'a été éprouvé que contre des réponses factices.
- Les libellés de types d'anomalies viennent de l'API ; l'écran n'en code aucun.
- Une lecture en échec ou déjà en cours arrête « Actualiser toutes les sources » (choix de réalisation).
- Le contrat `GET /sources` a été déclaré dans `contract-changes.yaml` (litige accepté) mais `specifications/openapi.json` devait encore être régénéré par la porte de contrat au moment des arbitrages.
- Les modifications de la v2 (`SourcesPage.tsx`, `notify.tsx`, clients) sont dans l'historique ; celles de la v3 (masquage des NIR, lecture « Pros », rapprochement par NIR) sont dans l'arbre de travail, non commitées. Aucun test de navigateur, aucune porte ni aucune suite n'a été exécuté pour ce résumé.
